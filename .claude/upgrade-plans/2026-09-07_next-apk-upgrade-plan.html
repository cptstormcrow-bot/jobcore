The APK sideloads as an in-place upgrade only when three things hold simultaneously: the package id matches exactly, the signing certificate matches exactly, and the new build's versionCode is strictly higher than the one already installed. If any one of those differs, Android treats it as a different app and either refuses the install or installs it side by side rather than upgrading. That is why the pre-flight and verification steps below check all three every time, not just once.

2. Pre-flight checklist

  1. Branch/status check: git branch --show-current and git status --short
  2. Confirm app.json expo.android.package is still com.sdassemblypros.jobcore.v2
  3. Confirm build.gradle applicationId/versionCode lines (89/91 area). Because android/ is gitignored, app.json bumps do not propagate to build.gradle automatically - either hand-edit build.gradle (keeps the native build cache) or re-run npx expo prebuild --platform android (regenerates from app.json; adding --clean wipes android/ and forces a slow full rebuild)
  4. Confirm app\apps\mobile\.env exists
  5. Run bare subst and confirm no Z: is already mapped
  6. JAVA_HOME plan: per-command prefix only, never a persistent env change
  7. No adb, no pairing, no USB-debugging prompts
  8. Keystore check (speed-up F, verify-first)
  9. Do not run ./gradlew clean and do not run expo prebuild --clean unless android/ is missing or broken
  10. app.json may carry unrelated unstaged hunks - stage only the versionCode hunk
