Security Posture — RLS Hardening Evidence

Row-Level Security (RLS) tenant-isolation hardening was verified against the live production Supabase project on 2026-08-13, in two passes:

  • An 8-suite hosted RLS run found 4 failing suites: AC-7, AC-8.2 (genuine RLS/trigger defect), AC-RV-2 (genuine RLS/grant defect), and AC-12.1c (a test-authoring gap, not a production defect).
  • A same-day follow-up fixed 3 genuine production defects via migration supabase/migrations/0013_rls_fixes.sql (idempotent, standalone-runnable):
    1. jobs_select_org SELECT policy — now requires both organization_id = current_org_id() AND is_org_sales_or_above().
    2. jobs_update_org UPDATE policy — now requires both organization_id = current_org_id() AND is_org_admin() on both using/with check.
    3. A new job_exists_in_org() security-definer function backing a fixed reviews_insert_anon policy.
  • AC-RV-2 was re-examined post-fix and traced to a test-file ordering bug (a stray reset role; running one statement too late) — no production defect remains; informational only.
  • All 4 suites were reverified against production on 2026-08-13: AC-7 PASS, AC-8.2 PASS, AC-RV-2 diagnosed (test-file issue, not app), AC-12.1c PASS.
