Appendix B: Handoff & Deep Links

🟢 Built & Live The customer-facing handoff page (`web/handoff`) is where a homeowner lands to pay or review a job outside the mobile app. Token resolution is implemented in router.ts's readTokenFromLocation():

  • Path form: /handoff/{token} — the token is the last non-empty path segment, provided it isn't the literal segment handoff.
  • Query form: ?token=... — checked first; if present it wins over the path segment.

Stale reference: 00-MASTER-SPEC.md documents the handoff URL as /j/{token}. That path does not match the as-built router. The working form is /handoff/{token} (or the ?token= query form). Treat the master spec's /j/{token} reference as superseded by this appendix until the spec itself is corrected.

router.ts's initialState() also carries a payer-skip rule: a partner-paid job (job.payer !== 'customer') opens directly at the review state and never shows the payment picker — this mirrors the same job.payer !== 'customer' skip the Payment & Review module's buildTransitionCtx applies for hasPaymentRecord (see Chapter 6). The review and done handoff states are valid, reachable router targets but are unbuilt screens as of this slice.

The awaiting_payment screen

🟢 Built & Live For a customer-paid job, the handoff page opens at awaiting_payment, rendered by awaitingPayment.ts's renderAwaitingPayment(). This is the real, on-site payment-provider picker: it lists the job's enabled providers (job.providers) as buttons, and on selection requests that provider's HandoffAction via requestHandoffAction(). The action is then followed by kind:

  • link / qr — the page navigates away to action.url (the provider's hosted checkout or a QR-code target URL).
  • in_app — there is nothing further this page can do; it advances to a confirming state and hands off to the mobile app.

Forward cross-reference (resolved in Slice 11): Chapter 4's "Collecting Payment from the Homeowner" subsection walks the Field Tech's side of this same flow. This appendix documents the handoff page's own provider-picker mechanics; Slice 11 wires an explicit link from Chapter 4's payment-collection subsection back to this appendix section (#appendix-b-awaiting-payment-screen) once that subsection exists as an assembled fragment.

Appendix C: Component Reference

🟢 Built & Live JobCore's shared UI package (packages/ui) is the mockup/component catalog used across the mobile app's module screens. As built today, it exports:

  • tokens — the design-token source (see Chapter 7's token translation reference).
  • Button
  • Card
  • ListItem
  • EmptyState
  • LoadingState
  • ErrorState
  • TextField
  • DatePicker

🟡 Built, Not Wired Footnote: Checkbox.tsx and Toggle.tsx exist as component source in packages/ui/src and are compiled to dist/Checkbox.js and dist/Toggle.js, but neither is re-exported from the package's barrel file (src/index.ts). A consumer importing from the package root cannot reach them today; they must be imported by their own module path, or the barrel export must be added.
